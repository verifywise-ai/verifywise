# VerifyWise Master Feature Matrix

This document is a unified, end-to-end map of every user-facing VerifyWise feature. It links the React frontend routes/components, the Node.js/Express backend APIs, the database models, access rules, existing tests, and user-guide documentation in a single table.

**How to read this matrix:**

- **Feature name** — the user-facing capability or screen.
- **Module / category** — the high-level product area (Core, Inventory, Assurance, Governance, AI Product, Admin, Public, Supporting Modules, Platform).
- **Frontend route(s)** — the URL paths registered in `Clients/src/application/config/routes.tsx`.
- **Page component file(s)** — the primary React/TypeScript page components that render the routes (relative to `Clients/src/presentation/pages/` unless otherwise noted).
- **Backend API base path(s)** — the Express route prefixes mounted in `Servers/app.ts`.
- **Key controller/route file(s)** — the primary backend controller and route files (relative to `Servers/`).
- **Key model(s) / table(s)** — the Sequelize models and PostgreSQL tables that back the feature.
- **Access / role requirements** — minimum access level (`Public`, `Any authenticated`, `Admin`, `Super Admin`, etc.).
- **Existing e2e test file(s)** — Playwright specs in `Clients/e2e/`.
- **Existing backend test file(s)** — Jest controller/integration tests in `Servers/`.
- **User guide article link** — matching article in `shared/user-guide-content/content/` (`.ts`) or `docs/user-guide-audit/` (`.md`).
- **Notes / gaps** — caveats, hidden routes, backend-only behavior, or known coverage gaps.

Paths in this document are written relative to the repository root for readability.
